# AI Teacher · 本地学习工作台 V0.4

> 当前为开发阶段的源码版本，尚未发布桌面安装包或稳定版 Release。已知生产依赖 `fast-uri@3.1.2` 存在安全审计告警，修复和重新验证前不建议用于正式部署。发布检查与已知限制见 [发布检查报告](docs/RELEASE-READINESS.md)。

## Windows 桌面应用

已新增独立桌面窗口、原生菜单与桌面设置，可自动启动/停止本地服务，保存窗口大小，并选择已有学习数据目录。成品入口是 `dist/AI Teacher-win32-x64/AI Teacher.exe`，开发入口为 `start-desktop.cmd` 或 `npm run desktop`。模型配置和教学工作流沿用现有工作台。此版为免安装应用文件夹，详见 [桌面版说明](docs/DESKTOP.md)。

平台维护数据、Web、提示词与业务状态。V0.3 新增可选 API 执行器：按模块调用用户配置的模型；未配置模块仍由 Codex / DeepSeek Harness 宿主执行。原始规格是产品参考，用户后续确定的本地架构与范围优先。

## 主页：从想法到学习目标

主页以大幅 AI 对话区为主，右侧提供学习日历；窄屏时日历移到对话下方。五项草案不再常驻主页，生成后通过“查看目标草案 / 查看并确认”打开弹窗编辑。日历支持月切换、按天查看、添加/编辑学习日程和标记待办完成；已有复习计划按复习日期自动显示。可将已有学习安排放到指定日期，尚未排期的路线不会自动占用某一天。日程完成不作为能力掌握证据。

在“学习概览”直接与 AI 讨论模糊想法，无需先填写目标。AI 每轮围绕一个关键问题，先明确学习范围、期望层级和具体成果，再整理为可编辑草案：学习方向、当前基础、期望达到的层级、具体能做什么、本次暂不涉及的内容。

讨论、输入中的文字和 AI 草案自动保存；可从下拉记录继续，也可新开独立讨论。手动编辑草案后点击弹窗中的“保存”；AI 对这些字段的改变会显示为待接受建议。点击“确认创建”才创建正式目标，进入目标内 Teacher 对话；草案和关键摘要随目标保留，并可回看完整探索记录。创建前不计入目标数量、不进行正式能力诊断、不关联材料。

主页复用“普通对话”模块的 API 或宿主配置。API 模型须支持 function tools 才能提交结构化草案；普通文字回复不会被冒充为已保存的草案。主页仅提供最近 30 个目标的名称、状态和每个目标最多 1,200 字的画像摘要，不读取资料正文、笔记或其他历史对话。第一次启动新版会在数据目录 `backups/` 中生成 `before-goal-discussions-*.sqlite` 备份，再升级对话结构，原目标和消息保留。

详细边界和接口见 [主页目标讨论](docs/GOAL-DISCUSSIONS.md)。

## Codex 自动唤醒（V0.4）

在“模型与分工”启用 Codex 自动唤醒，即可直接从 Web 连续对话，无需复制提示词。本机服务按消息启动后台 Codex，复用已有登录，并通过任务专用 MCP 回写回复。支持登录检查、模型设置、暂停与失败重试。详见 [自动唤醒指南](docs/HOST-AUTOMATION.md)。DSH 自动唤醒尚未适配。

## 按模块选择模型（V0.3）

打开“模型与分工”→“添加模型连接”，填写连接名称、Base URL、准确模型名及 Key。可以先保存、稍后填写 Key；保存不会发出请求。选择每个模块的连接，然后启用 API 执行器。详细说明见 [模型配置指南](docs/MODEL-ROUTING.md)。

模块包括：普通对话、资料分析、能力要求、学习路线、诊断与学习考察、复习与强化、最终综合面试。同一服务商的不同模型可以添加成多个连接。配置仅影响新任务；已有等待任务可以在对话中重试或改由宿主/API 处理。

支持 OpenAI 兼容 Chat Completions 和 function tools。不是任意服务商原生 API；Anthropic 原生 Messages、OpenAI Responses 和需要特殊推理扩展的模型尚未适配。没有真实 Key 时只进行本机模拟验证。

## 启动

本机地址：http://127.0.0.1:4317/ 。Windows 双击 start.cmd，或在本目录运行 node server/index.mjs。已有服务运行时不要重复启动。需要 Node.js 22.13+，当前使用 Node 24。

首次安装：npm install。需要手动连接宿主时运行 node scripts/configure-plugin.mjs；脚本按自身位置定位项目，不依赖终端当前目录。Git 只保存配置模板，实际插件配置 plugins/ai-teacher/.mcp.json 和 DSH 配置 .local/deepseek-harness.yaml 在本机生成并被 Git 忽略。移动项目或切换 Node 安装后需重新生成并安装插件配置。桌面内自动唤醒无需这一步。

数据库是独立的 SQLite 文件 data/teacher.sqlite，无需数据库服务。升级到 schema v2 前自动生成 data/backups/before-v02-*.sqlite 一致性备份；原记录保留。完整日常备份请先停止服务再复制 data 目录。JSON 导出不是完整数据库备份。不要分享 data/agent-token 或数据库中的私人学习资料。

## V0.2 保留的六项能力

| 方向 | 本版支持 |
| --- | --- |
| 能力要求与达成判断 | Core/Supporting 能力项、知识点要求、用户确认与版本历史、证据关系及自然语言判断 |
| 资料处理 | 本地文件选择与副本保存（单文件最多 20 MB）、原文件下载、网页链接、粘贴正文；UTF-8 TXT/Markdown 在 15 万字符内自动导入正文，保留约定范围、版本与哈希；文件保存不代表已读 |

资料库显示全部收藏。添加资料默认打开“本地文件”入口，点击“选择文件”唤起系统文件选择窗口；也可切换到网页链接。学习目标与资料用途收在可选设置中，不关联目标也能收藏。PDF、Word、PPT 等当前保存原文件，尚不自动提取正文；要让 Teacher 分析，需关联学习目标并提供可读正文。原文件保存在 SQLite 中，完整数据库备份会包含文件；JSON 导出不包含文件附件。
| 学习路线 | 初始诊断后提出阶段→主题→学习安排，关联要求、材料与先修依赖；校验覆盖和循环依赖，用户确认后启用 |
| 考察 | 初始/增量诊断、资料考察、学习/复习/强化/自由测试、复核及最终面试；开闭卷、逐题问答、结束后反馈、提前结束 |
| 缺口与复习 | 记录缺口，忽略/强化/安排复习，按证据解决或再次打开，指定日期和修改日期，完成目标后继续复习 |
| 目标结束 | 最终综合面试后用户确认完成，或主动终止；结束快照和归档，不能重新激活 |

12 种考察类型共用一套结构化问答状态机，本版没有为每种类型实现独立的全套教学策略。学习安排“已完成”表示考察流程已记录，不自动等于能力达成。最终完成采用保守条件：核心要求均有支持证据、无未解决核心缺口、最新最终面试建议完成。

V0.1 的目标、对话队列、笔记、提示词历史、暂停/恢复、旧路线和证据继续保留。旧版考察仍可使用；转入新流程需先确认能力要求。

## 开始一次实际学习

1. 创建目标，在资料库添加材料；粘贴正文或导入 TXT/Markdown，填写约定范围。
2. 在“评估与复习”点“请 Teacher 评估与规划”。在宿主启用新版 AI Teacher 并处理 Web 消息。
3. Teacher 读取正文、保存分析，提出能力要求。你在 Web 确认后发起初始诊断。
4. 在 Web 逐题回答。Teacher 结束诊断并根据证据提交学习路线，你确认后开始学习。
5. 在路线中选择学习考察，或指定资料发起自由测试。查看缺口与复习安排；最后发起最终综合面试并确认结束目标。

## Codex / DSH 宿主

安装或更新 ai-teacher@personal 后，请开启新的 Codex 任务以加载新版技能和 15 个工具。保持本地服务运行，发送：

> 使用 AI Teacher 插件，处理 Web 中的待处理消息。按 V0.2 工作流进行资料分析、能力评估和路线规划；通过 MCP 将所有用户可见回复和正式考察问题写回 Web。

以下为手动宿主方式；启用 V0.4 自动唤醒后无需执行。需要连续交流时，明确要求“在本次运行中持续处理 Web 消息，直到我要求停止”。宿主停止后不会继续回应，MCP 本身不唤醒宿主。当前按整条消息同步，非逐 token 流式，也不镜像宿主的其他对话或内部推理。

插件源码 plugins/ai-teacher；通用模板是 .mcp.template.json，本机生成的 .mcp.json 定位 stdio 适配器。宿主可能从任意目录启动，所以本机生成文件使用解析后的路径，仓库模板不含机器路径。亦支持 /mcp Streamable HTTP。DSH 模板见 docs/deepseek-harness.yaml，实际使用生成的 .local/deepseek-harness.yaml；本机未进行真实 DSH 模型联调。两种 MCP 传输通过 SDK 客户端验证。

## 自定义 API

接口定义：docs/openapi.json。用户操作使用本机页面签发的 HttpOnly 会话 cookie。Agent 调用 POST /api/agent/tool，使用独立 Bearer token，不能调用用户确认接口。

请求示例：{"name":"teacher_claim_message","arguments":{"host":"my-host","wait_seconds":0}}。

工具涵盖：对话列表/上下文、领取/续期/回复、旧路线/旧考察、新能力提案、资料读取/分析、结构化路线、逐题提问/反馈/结论和复习安排。request_id 每项逻辑操作唯一，重试复用；领取令牌 3 分钟有效。

## 明确的后续范围

- PDF/PPT 自动解析、OCR、网页抓取、语义检索尚未实现；当前可复制文字或导入纯文本。
- 跨目标知识树、节点拆分合并、复杂证据冲突仲裁、自动笔记触发和滚动复习调度尚未实现。
- 先修依赖被保存和校验，但尚不强制锁定学习顺序；路线页面目前按阶段/主题标注列表，未做图形编辑器。
- 没有常驻宿主调度器或公网多用户支持。
- 结构校验不能保证 AI 的教学判断正确；真实材料上的长期教学质量仍需使用中评估。

## 验证

运行 node --test tests/*.test.mjs 与 node scripts/check.mjs。测试使用独立临时数据库，覆盖旧版回归、两种 MCP 传输、结构化学习闭环、缺口与结束条件、迁移备份和持久化。浏览器检查覆盖能力确认、创建诊断、等待状态、提前结束和资料正文表单。测试数据不写入实际学习库。
