# V0.14.3 · 对话反馈、Enter 发送与 DSH 联网

## 交互与执行记录

各主要对话输入区共用键盘处理：Enter 发送、Shift+Enter 换行，输入法组合期间不提交；提交中的禁用按钮不能被快捷键绕过。修复了画像页此前完全没有 Enter 事件的问题。

DSH 回合现在展示准备模型／会话、启动宿主、等待模型、实际推理或内容生成信号、工具开始和完成、回复正文生成，以及取消／失败／完成状态。工具记录包括联网搜索、网页读取和受限 Teacher MCP 操作。耗时由本地时钟显示；30 秒没有新事件会说明“未收到新进展”，不编造执行阶段。

界面只投射阶段、工具名称、开始结束时间和固定错误类别，不展示模型内部推理正文、工具参数／结果全文或原始服务商错误。正文继续通过现有流式通路显示，正式消息由 SQLite 写回决定。

进度通过同一条 SSE 的 `run-progress` 事件发布；`/api/run-progress` 提供用户会话鉴权的快照，支持刷新续接。内存保留最多 100 个回合，每回合最多 30 项工具记录，结束后 10 分钟过期；重启应用后不声称仍有完整历史工具轨迹。取消后拒绝迟到进度。

## DSH 联网

此前 AI Teacher 的临时 patch 明确禁用了 `tool-web`。新版执行回合开放原生 `web_search` 和 `web_fetch`，复用 DSH 全局／headless／Desktop 的内置 web 服务配置；目录探测进程仍不启用联网工具。文件、Shell、子 Agent 等无关工具仍禁用。

Qoder 等对话模型与搜索提供商是不同配置。DSH 默认搜索服务使用独立 DeepSeek 凭据，选择 Qoder 不会自动提供这把 Key。模型得到真实工具结果后才能引用搜索来源；工具失败需要如实说明，不能声称已联网检索。

新增“模型与分工 → DSH 联网 → 设置本机代理”。设置保存在学习数据目录的 `dsh-network.json`，只传给 AI Teacher 启动的 DSH 进程及模型目录探测；不修改系统代理或 DSH 源配置。仅接受不带凭据的本机 HTTP(S) 代理，loopback MCP 通信通过 NO_PROXY 保持直连。

本机实测发现公共域名被解析为 `198.18.*` 虚拟地址，DSH 的公共网页策略会拒绝。用户授权单独使用本机 `http://127.0.0.1:7897` 后，原生 `web_fetch` 已能读取 Python 官方文档。原生 `web_search` 仍返回 `WEB_PROVIDER_CREDENTIAL_MISSING`；搜索需要用户在 DSH 配置对应凭据，不能把“工具可见”当作“搜索成功”。不要将 Key 放进对话。
