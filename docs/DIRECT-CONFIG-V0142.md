# V0.14.2 · 直接配置与模型列表提速

## 主 Agent 直接设置

新增 `teacher_set_agent_configuration`。主 Agent 读取最新配置的 revision 后，可按用户要求设置各功能的 DSH、Codex、Claude、手动 MCP 宿主、DSH 模型或已有 API 连接。返回 `APPLIED` 表示已经生效，不需要设置页二次确认，也没有新增授权开关。

- 工具只提供给主 Agent，校验配置对话、任务归属、有效租约和配置版本。普通学习功能不能调用。
- 不能修改主 Agent 自身、新建 API 服务地址、密钥或可执行文件路径。已有宿主路径保留或复用，不把原来的自定义安装路径清空。
- DSH 模型必须在当前目录；未指定模型时解析目录默认值。新 API 连接继续用原提案与表单。
- 多个功能在同一事务内更新，重复 request_id 不会重复执行。配置影响后续任务；已排队的显式模型选择和对话独立选择保留，等待中的失败任务不自动重试。
- 受影响功能仍在执行时拒绝变更，避免中断运行。用户取消主 Agent 当前任务后，其租约不能继续写入。
- `agent_configuration_changes` 保存无密钥的变更前后配置。首次创建前生成一致性备份。设置页提供撤销；后续配置版本变化时不覆盖更新后的设置。
- `teacher_propose_agent_configuration` 保留用于用户只要方案或需要新 API 连接的情况。直接设置会将旧待确认方案标记过期，避免再次应用旧方案。

能力要求、学习路线、长期画像和目标结束的确认规则未改变。

## 模型目录加载

旧版本首次请求会阻塞到 DSH 完成探测、插件加载和目录查询，且目录只存在内存。新版普通读取立即返回声明或此前已验证的缓存，后台同步完整目录；通过现有 SSE 发送 `dsh-model-catalog`，页面收到后更新选择器。没有缓存的首次运行可能先显示普通提供商，状态栏明确说明插件模型正在同步。

持久缓存位于数据目录 `dsh-model-catalog/teacher-model-directory.json`，仅保存名称、ID、来源、诊断类别、检查时间与配置指纹。配置和插件入口变化会使缓存失效；损坏或失败的缓存不伪装成已验证结果。刷新按钮强制重查。已有目录项的选择保存不重复启动 DSH，实际执行继续检查模型与适配器。

配置扫描复用依赖文件清单，以文件状态检测变化，避免每次重新读取和解析插件源码。没有删除源配置，也没有复制凭据。

2026-10-29 本机目录基准（40 个模型，单次测量，非 UI 总加载时间）：

| 阶段 | 耗时 |
| --- | --- |
| 无缓存时立即返回初始目录 | 84.11 ms |
| 首次后台完整注册表校验 | 14,731.29 ms |
| 重启后从持久缓存读取完整目录 | 21.04 ms |
| 后续目录读取平均值（20 次） | 3.17 ms |

此优化不声称降低云模型推理时间。命令：`node scripts/benchmark-dsh-catalog.mjs`，结果位于本机 `outputs/dsh-catalog-speed-v0142.json`。
