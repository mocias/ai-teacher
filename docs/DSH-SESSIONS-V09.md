# DSH 持续会话与 AI Teacher 共享工作区 · V0.9.1

AI Teacher 的所有相关对话共用一个工作区。每段站内对话对应一个活动 DSH 会话，后续通过 `--session-id` 持续恢复；消息、上下文和检查点按会话保存。进程逐轮启动，站内 SQLite 保存正式消息、学习状态及执行结果。

## 目录布局

路径随当前学习数据目录定位：

```text
data/
  teacher.sqlite
  ai-teacher-workspace/                 # 所有相关对话统一的 DSH 进程 cwd
  dsh-runtime/conversations/<对话哈希>/
    g1/                                # 第一代会话的运行数据
      profiles/headless/
      sessions/                        # 此会话的原生 JSONL 日志
      checkpoints/latest.jsonl         # 最近一次完整成功的检查点
    g2/                                # 明确重建后的下一代，旧代保留
```

各对话的 `cwd` 相同，可共享工作区文件；session ID、历史和恢复数据分别保存。工作区目录不再按对话创建。完整备份应在退出软件后复制整个学习数据目录，包含 SQLite、共享工作区及会话运行数据。JSON 学习导出不包含运行时文件。

模型与服务商配置按功能设置、DSH 全局/headless 明确设置、Desktop 设置的顺序选取。DSH 凭据服务从原 DSH home 读取凭据，不复制到共享工作区。会话运行时仅初始化随附 headless profile，不加载 Desktop 或其他用户 profile 的任意插件。文件、命令、浏览器和子 Agent 等内置工具继续关闭。

## 会话与每轮执行

`dsh_sessions.conversation_id` 为主键，活动 `session_id` 唯一；`harness_runs` 记录本轮的 session ID 和共享工作目录。首次执行记录 DSH 返回的真实 session ID，此后同一对话持续复用。

每轮 MCP 配置和 Token 重新生成，结束后撤销。恢复后的模型必须先调用 `teacher_get_context`，再执行本轮其他工具。工具继续绑定当前角色、消息、租约、目标、资料和考察，历史凭据不能使用。

上一宿主退出前，下一宿主不能领取同一对话的新任务，包括跨功能切换。回复已经写入但 DSH 尚在落盘时仍保持此限制。不同对话的 DSH 会话可分别运行；当前仍按功能串行调度，共用工作目录不合并对话历史。

检查点只在站内回写完成、DSH 正常退出且报告完整 turn_end 后更新。复制后同步文件并保存 SHA-256。终端文本不作为正式回复写入学习库。

## 恢复与维护

“模型与分工 → DSH 对话会话与工作区”统一显示共享工作区路径，下面列出最近 100 个对话映射及其状态：等待首次执行、执行中、可继续、上次执行失败、执行曾中断、需要恢复。

- **检查会话**：检查会话 ID、工作目录及 JSONL 记录，也能找回日志已落盘但数据库未记录的唯一会话。不调用模型、不重试学习任务。
- **从检查点恢复**：用户确认后，校验会话 ID、工作目录和 SHA-256，恢复最近一次完整成功的日志。被替换的原日志另外留备份。站内消息和学习状态保留，未完成任务仍需显式重试。
- **重建会话**：用户确认后，归档旧映射并增加代数，保留旧日志、检查点及共享工作区文件。下一轮从站内历史创建新会话。失败不会自动触发重建。

服务重启将未结束的映射标记为中断，任务保留阻塞状态，不自动重放已完成消息。记录的旧 DSH 进程仍活着时拒绝并发恢复。数据目录移动导致原生日志的绝对 cwd 不一致时，需恢复原路径或明确重建，不静默修改日志。

## 兼容旧版

首次建立映射前的旧一次性 DSH 日志没有可靠的站内归属，保持原样；已有站内对话在下一次 DSH 调用时从站内历史初始化。

V0.9.0 曾按对话创建工作目录。升级到 V0.9.1 时，数据库增加 `workspace_layout`，迁移前备份为 `backups/before-dsh-shared-workspace-*.sqlite`。旧映射在下一次调用时归档，并在共享工作区建立下一代会话；原 session ID、日志路径及工作区文件保留，不直接改写 DSH 原生日志的 cwd。站内历史继续提供给新会话。已采用共享工作区的映射在重启和后续调用中继续使用相同 session ID。

## 验证

- `npm test`：会话映射唯一性、共享 cwd、各会话恢复数据分离、重启、并发锁、上下文刷新、Token 撤销、日志/检查点损坏、明确重建、旧布局兼容、目录链接拒绝及 HTTP 权限。
- `node scripts/smoke-dsh-local.mjs`：真实安装版 DSH、真实 stdio MCP、本地确定性模型。覆盖连续多轮、重启续接、两个对话相同 cwd 且不同 session ID、共享文件可见、中断重试、检查点恢复和重建保留旧日志。
- `node scripts/smoke-desktop.mjs --packaged --dsh`：成品启动、自动检测、配置重载及共享工作区管理入口。上述模型测试不消耗云服务额度，不代表教学质量评测。
