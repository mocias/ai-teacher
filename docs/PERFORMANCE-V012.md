# V0.12.0 · 界面与加载优化

## 界面

首页直接呈现目标讨论，把当天安排、继续阅读、目标下一步、日历和配置提醒放入右侧栏。右侧独立滚动，桌面窗口保持输入区可见；窄视口按单列排列。导航改为浅色背景，统一卡片、按钮、对话气泡、留白与文字层级。首屏显示加载占位，明确正在连接本地服务。补充消息区键盘滚动、日历区域语义、文字对比度和减少动态效果偏好。

## 加载与刷新

- 每个文档只有一条 SSE，业务状态与正文预览共用。阅读器 iframe 是独立文档，进入后拥有自己的连接；主页面在显示阅读器期间暂停后台刷新。
- 100ms 内突发通知合并，刷新请求串行，运行中又收到更新时补刷新一次。正常连接不再每 5/10/15 秒轮询；隐藏文档暂停刷新，回到前台立即同步。断线时自动重连并提供 60 秒备用检查，跨日也会同步。
- 首页只读取当前目标讨论；其他页面不再顺带读取未打开的 Teacher 聊天。会话缓存最多保留 20 项，切换先显示已有内容，再同步最新状态；旧请求返回时检查当前页面与对话，防止串话。
- 后台状态和消息未变化时，不替换主页面 DOM；个人画像和阅读答疑也复用未变化的消息节点。草稿、焦点、选区、阅读位置继续保留。
- Markdown 继续经过 DOMPurify 和链接处理后才显示。清理结果有 160 项、约 200 万字符的缓存上限；不是绕过清理。
- 公共 HTML、CSS、JS 和 PDF.js 资源采用内容 ETag，未修改时返回 304。服务器异步读取，并以 32 MiB 上限缓存资源；每次检查文件状态，源码修改和版本升级会重新校验。API、资料正文和附件保持原有鉴权与 no-store。
- 定时后台工作的数据库变更也会发布通知，包括租约恢复和学习修改合并，避免取消轮询后漏更新。慢 SSE 连接断开后重新同步。

## 实时过程的范围

现有 DSH 插件仅把 `teacher_reply` 的正文片段投射到聊天。截图中的完整过程还需要新增思考／工具事件结构、运行与重试的归属、取消和保留策略、前端可折叠记录，以及相关验收；不是改一个显示开关。按本次“改动多则暂不做”的要求，本版暂缓这部分，保留并复测正文流式显示。没有把计时器、假文本或终端输出当作思考过程。

## 验证与读数

使用临时 SQLite、独立桌面配置和本地模拟模型，不修改实际学习数据或消耗云端模型额度。

- `npm run build`：语法和必需资源检查。
- `npm test`：128 项通过，含新增资源缓存、鉴权、单连接、通知合并、隐藏状态、串行刷新和重连检查。
- `node scripts/smoke-desktop.mjs --performance`：真实 Electron 的启动请求、20 个通知合并、空闲请求数、DOM 与草稿选区保留、11 个页面切换、延迟消息请求切换隔离，以及桌面输入区与 560px Chromium 视口布局。
- `node scripts/smoke-desktop.mjs --chat-ui`：Markdown 安全显示、固定输入区、草稿恢复、失败保留、阅读位置和输入时接收真实 MCP 回写。
- `node scripts/smoke-desktop.mjs --reader`：内嵌阅读器、资料打开、多标签、网页章节恢复、阅读问答、标记与画像流程。
- `node scripts/smoke-desktop.mjs --streaming`：真实本机 DSH + 本地模型，验证未结束时可见、多个片段、刷新续接、保存去重、取消半段不保存和快照鉴权。

已有目标讨论时，首页启动为 **1 次 `/api/state`、1 次 `/api/messages`、1 条 SSE**；旧实现会在初始刷新、首次 SSE open 中重复取状态及两种对话。全新数据首次创建目标讨论需要额外写入与同步。正常 SSE 连接的空闲 16 秒测试为 **0 次额外数据请求**，连续 20 个通知合并为 **1 次状态 + 1 次当前消息请求**。

请求数量和重绘减少是本版直接验证的改善；页面切换记录只计同步渲染耗时，不等于服务商推理速度或大型真实数据库的端到端延迟。未声称云模型首字延迟获得相同比例提升。未做大规模数据压力测试，PPT 转换不是本次验证范围。
