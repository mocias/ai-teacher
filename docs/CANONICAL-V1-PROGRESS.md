# Canonical V1 实现与验收

依据 2026-09-11 的《AI Teacher Platform — Canonical V1 Specification》和用户随后圈出的六项优先需求。用户主要在站外自学。Teacher 负责材料组织、规划、基于作答的诊断和后续安排。实际学习进度、能力证据、用户意愿分别记录。

| 分片 | 用户可验证的结果 |
| --- | --- |
| 长期能力画像 | 在新目标看到另一目标的原题、回答、开闭卷及反馈。相同知识点可承担不同要求。跨领域引用、画像变化和知识结构调整可以回查原证据。 |
| 材料与初始化 | 按目标和正文版本核对已覆盖、遗漏或矛盾的要求。初始主材料须按约定范围分析。活动目标中一个主题的矛盾只阻塞该范围。 |
| 学习路线 | 保留已确认路线与既有任务 ID，在有先修、延后和阻塞的情况下展示最近 N 个可执行安排。用户恢复延后项，移除单课与排除主题分别处理。 |
| 考察与笔记 | 快速自测先了解已学范围，再做针对性提问。笔记可以产生验证邀请，只有实际回答产生证据。开卷检索提供原文与来源。 |
| 缺口、复习与自然周 | 复习强度可调，后续安排引用实际回答，可改期和取消。自然周按领域与全局分别呈现实际学习、证据和仍待处理的问题。 |
| 目标结束 | 最新最终面试、当前能力版本、核心要求、核心缺口和关键材料冲突共同约束结项。确认完成或终止后保留当时的快照。 |

## 集成验收

1. 使用隔离库，导入资料并走完第一个目标。建立第二个目标，比较两个目标对同一知识点的不同要求，追溯原作答并短测。
2. 在同一条已确认路线中设置受阻主题和可执行主题。验证延后、恢复、替补、先修、用户裁决，以及旧任务、日期和历史的保留。
3. 区分已读、写笔记、作答、获得支持性证据和正式结项。重试与重启不能复制安排或证据，自动安排不得覆盖人工操作。
4. 运行源码回归，在隔离数据目录运行桌面成品；分别记录本机固定模型流程和真实教学质量的验证范围。版本目录与实际 EXE 必须对应。

## 在工作台中使用

- 在「学习管理 → 目标进度」确认当前能力要求后，查看其他目标的作答依据并发起短测。新路线会解释为什么可以省去重复内容，引用的原考察可以打开。
- 在「设置 → 学习画像」打开长期画像。知识点引用稳定 ID，同名概念不会跨领域自动合并。主题重组和画像整理先给出提议，用户可以检查原回答、影响范围，再决定是否采用。
- 在资料库或阅读器选择「用于正式学习」，为每个目标确认用途、范围和正文版本。在目标进度中核对材料，有冲突的主题会显示两份来源。
- 「学习路线」显示近期任务及没有入选的原因。「周复习」显示当周日历、作答证据和复习安排，可设置容量及领域顺序，预览后排入日历。自动安排后续复习默认关闭。
- 在「评估」主动开始阶段自测并填写已学范围。开卷查到的原文可用于参考；笔记、查阅和学习时长不计为能力证据。

## 验证方法

在独立临时库运行源码回归，使用 `node scripts/smoke-desktop.mjs --canonical` 跑开发版，给同一命令增加 `--packaged` 并指定 `TEACHER_PACKAGE_DIR` 验证成品。桌面报告会记录该次是否经过真实界面，以及模拟模型实际调用过哪些工具。另可用 `--packaged --recovery` 验证失败复习、补学、强化、改期和最终结项。

更新已有库时会先在数据目录下创建一致性的 `backups/before-canonical-v1-*.sqlite`。兼容验收使用 V0.14.3 创建的隔离库，对比原有 63 张表旧字段的全部行，本版新增的新字段和表另作检查。

## 保留的边界

当前支持知识主题拆合，知识点本身的拆合及活跃能力要求的迁移尚未提供。不同表述的概念须明确匹配，开卷资料采用原文关键词检索。周排期根据用户输入的容量和时长计算，复习强度提供可调整的间隔，不推断个人精确遗忘时间。没有经过长期真实学习效果评估。
