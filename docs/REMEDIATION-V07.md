# V0.7 薄弱点补学计划

日期：2026-10-19。本版在 V0.6 的考察结果与强化入口之间，增加可保存、可排期、可继续的补学任务。

## 使用

1. 从考察结果或目标下一步打开“回看资料与强化学习”，选择“安排补学到日历”。
2. 填写具体补学内容、日期、预计分钟数，并选择本目标的资料。默认内容是供用户编辑的通用提示，不是 AI 自动生成的补救课程。
3. 保存后，从首页“今天学什么”、日历或目标进度打开任务。记录进度和“下次继续什么”，可打开所选资料；打开资料和进入强化确认前会保存记录。
4. 下次打开应用，记录仍在。若当前路线考察已完成，且核心薄弱点有待完成补学，“目标下一步”会引导继续该任务。
5. 准备好后，点击“开始强化考察”并确认。补学进度 100% 不代表薄弱点已经解决；仍须新回答证据验证。
6. 目标进度保留“补学计划与记录”，支持改期、取消和回看已完成／已取消历史。取消不删除笔记、资料选择或来源依据。

## 数据规则

- 新补学必须来自学习中目标、当前已确认能力版本、尚未解决且有真实回答依据的薄弱点。暂停、终止、完成目标和旧版要求不能新建补学。
- 同一薄弱点已有待完成补学时，复用原记录，不覆盖日期、内容或进度。完成或取消后可另行安排；已有新的待办时，不允许把旧完成记录同时恢复为另一项待办。
- 补学日程独立于正式路线任务，不能把已有补学日程重新关联为路线任务。改期与取消使用原日历操作。
- 每项任务保留安排当时的薄弱点描述、原因、证据与能力版本。后续反馈变化不会改写原依据；旧能力版本记录保留，但不提供强化入口。
- 资料仅能选用本目标已有资料；不复制正文、不猜测章节、不自动新增路线。补学记录不会变成评估证据，也不会自动完成目标。
- 新增 `remediation_tasks` 表。已有目标的旧库迁移前生成 `backups/before-remediation-*.sqlite` 一致性备份。测试验证已有日程和学习内容保留、备份仅生成一次，以及重启后进度与来源持久化。
- 创建操作要求用户会话，Agent 凭据不可代替确认。日程、补学来源及幂等回执在同一事务保存，失败全部回滚。

## 交付与升级

独立成品：`outputs/desktop-v0.7.0/AI Teacher-win32-x64/AI Teacher.exe`。先退出旧应用和旧服务，再打开新版。沿用既有数据目录设置，正式学习库未用于测试或移动；原 `dist`、V0.5、V0.6 包和桌面快捷方式保留，旧快捷方式不会自动更新。

这是 Windows x64 免安装应用文件夹，需保留整个文件夹。尚未提供安装器、代码签名或自动更新。

## 接口

`POST /api/remediation/schedule`：输入 `gap_id`、`date`、`duration`（1–240）、`activity`（1–5000 字）、`resource_ids`（0–50 项）及 `request_id`，返回 `id`、实际 `date`、`reused`。`GET /api/state` 的 `remediation` 返回来源与任务关联；进度、日期和取消状态仍在 `calendar` 中。

后续记录复用 `/api/calendar/progress`、`/api/calendar`、`/api/calendar/cancel`。完整结构见 `docs/openapi.json`。
