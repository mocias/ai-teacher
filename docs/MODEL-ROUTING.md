# 按模块配置模型 API（V0.3）

## 使用方式

1. 打开 http://127.0.0.1:4317/ → 模型与分工。
2. 添加模型连接：填写名称/服务商、Base URL、模型 ID 和 API Key。同一服务商的多个模型可建立多个连接。保存配置不产生请求；Key 可以稍后填写。
3. 分别为普通对话、资料分析、能力要求、学习路线、诊断与学习考察、复习与强化、最终综合面试选择连接。未指定连接时使用 Codex / DSH 宿主。
4. 可点击“测试连接（调用 API）”发送一条短测试，消耗服务商额度。此测试只确认基本协议；教学流程还要求 function tools。
5. 启用 API 执行器。此后只要本机服务运行，API 任务就会被处理，不需要 Codex 持续等待。

资料库“请 Teacher 分析”自动使用资料分析模型；“请 Teacher 评估与规划”依据当前流程选择能力要求、路线或普通对话模块；考察按类型自动分配。普通对话输入框上方可选择本条消息的用途。一个任务只使用所属模块的模型，不会在普通对话中静默跨模块调用；需要其他模块时使用对应入口。

路线配置只影响新任务。已在等待的任务可在对话中选择“使用此模块配置的 API”或“改由宿主处理”。失败保留原消息并停止自动尝试；修正模型配置后点“重试当前模型”。同一对话的后续消息等待前一条处理、取消或重新分配。

## 连接参数

- Base URL 使用服务商的 API 根路径。例如带 /v1 的地址会调用该地址下的 /chat/completions；如果粘贴完整 /chat/completions 地址也会规范化。远程连接要求 HTTPS；本机 vLLM 等可使用 http://127.0.0.1:端口/v1。
- 模型名完全使用服务商提供的模型 ID，不由平台猜测或自动替换。
- Temperature、最大输出 tokens 为可选参数；不填写时不发送，使用服务商默认值。按服务商要求选择 max_tokens 或 max_completion_tokens。
- 每次请求默认 90 秒超时，可设置为 5–180 秒。每次任务执行最多 12 轮 API 请求，避免无限调用；超限后显式重试。
- 不支持工具调用的纯聊天模型只能用于普通对话。当前不适配 Anthropic 原生 Messages、OpenAI Responses、需要传回专用 reasoning 字段的推理模式或任意非兼容协议。

适配依据：[OpenAI Chat Completions 官方协议](https://developers.openai.com/api/reference/resources/chat)。工具参数由服务端校验，模型无权确认能力/路线或结束目标。

## Key 与数据

Key 在本机表单填写，不应发到聊天中。编辑时留空保留原 Key，勾选清除即可移除；修改 Base URL 必须重新填写或清除旧 Key。读取配置只返回“已保存”，不回显 Key。

Key 使用 AES-256-GCM 加密后保存到 data/teacher.sqlite，本地主密钥为 data/model-vault.key。两者都属于私密备份；拥有两份文件的本机进程仍可解密。学习 JSON 导出不含模型配置、Key 或内部执行 trace。浏览器不使用 localStorage 保存 Key。

启用 API 后，对应任务上下文会发送到你选定的服务商，包括目标、相关对话、活动笔记、证据和所选材料。归档笔记不会进入上下文。原始服务商错误响应不写入日志/页面；仅显示 HTTP 状态及本地错误原因。Token 用量按供应商返回值展示，没有费用估算。

## 验证边界

本次使用本机模拟 API 与隔离数据库验证协议、模块分配、工具执行、失败与取消、Key 持久化、用户接口权限和 Web 回复。不创建真实 Key，不调用真实收费模型。你填写实际连接后，仍需要验证该服务商的模型权限、工具调用能力和输出质量。
