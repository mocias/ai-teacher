# V0.6 复习反馈与强化学习

日期：2026-10-19。接续 V0.5 的资料 → 目标 → 路线 → 每日学习 → 复习闭环，补齐考察结果返回后续学习的入口。

## 使用流程

1. 完成考察后，对话顶部出现结果摘要和“查看结果与下一步”。评估页、复习页仍可回看原逐题记录。
2. 结果页列出本次回答实际涉及的要求及证据关系：支持、相反表现或尚不足判断。对当前版本的要求，可以安排下一次复习；日期和重点由用户确认。明天、3 天后、一周后仅是日期快捷选项。
3. 已有同一要求的待复习安排时，显示原日期并提供查看入口；不会重复创建或改写原来源。若已有安排关联的薄弱点与当前不一致，须先处理或取消原安排。
4. 复习页区分到期／进行中、未来安排与历史。可以查看安排依据、修改待复习日期或取消安排。取消保留记录和来源；进行中的复习须先结束考察，不能直接取消安排。
5. 结果页的薄弱点入口可回看当前已关联的学习资料和任务，并确认开始强化考察。路线考察完成后，目标进度优先提示尚未解决的核心薄弱点。
6. 新回答支持解决后，薄弱点才关闭；最终面试与用户确认结束的原有规则保留。

## 数据与行为边界

- 新复习保存来源考察与回答证据，要求来源考察已完成、证据实际涉及所选要求，且仍对应当前已确认的能力版本。暂停或终止目标不能新增后续复习；完成目标可以保留长期复习。
- 能力要求更新后，旧结果和复习继续作为历史保留，不再驱动新版要求的后续安排。旧复习没有来源时，不补造来源关系。
- 结果页同时展示“本次回答证据”和“当前仍未解决的薄弱点”。一次其他考察中的支持性回答，不会自动抹去已有薄弱点的验证流程。
- 回看资料、取消复习、取消强化确认、学习进度达到 100%，均不产生新能力证据，也不将薄弱点标为已解决。
- 两个新操作仅允许用户会话调用；Agent 凭据不能代替用户确认。复习、来源、缺口状态和重试回执在同一事务中保存，失败全部回滚。
- 新增 `review_sources` 表。已有目标的库首次迁移前生成 `backups/before-review-followups-*.sqlite` 备份；测试验证旧安排保留、只备份一次和重启持久化。正式学习库未用于本次测试。

## 打开新版

入口：`outputs/desktop-v0.6.0/AI Teacher-win32-x64/AI Teacher.exe`。先关闭旧窗口和旧服务，再打开新版。新版沿用原桌面应用的数据目录配置，未移动或合并正式学习库；原有 `dist`、V0.5 成品和桌面快捷方式保留，旧快捷方式不会自动指向新版。

这是免安装 Windows x64 应用文件夹，尚未提供安装器、代码签名或自动更新；转移应用时需保留整个文件夹。

## 接口

- `POST /api/reviews/followup`：`source_assessment_id`、`requirement_id`、`due_date`、`reason`、`request_id`；返回 `id`、`reused`、实际 `due_date`。
- `POST /api/reviews/cancel`：`id`、`request_id`；取消待复习安排，保留来源及未解决薄弱点。

完整结构见 `docs/openapi.json`。
