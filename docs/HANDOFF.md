## V0.17.4 避免题干与追问相互泄露答案

共享教学提示词扩大到开放题、选择题、比较题和计算题。模型出题前先明确未知结论，再检查整段题干、后续小问、括号、反问、选项和可见反馈是否预设或泄露答案；依赖前一结论的追问通常留到真实回答后，且先核实用户的前提。相互独立或递进但不透露前问结论的小问、明确的已知条件，以及用户需要提示或直接讲解的情境均保留。

仅修改 `server/question-guidance.mjs` 的提示词文本及版本标识；没有关键词拦截、固定题数、自动拆题或重新判分。任务学习和正式考察继续通过既有共享提示词入口读取。既有题目不改写，真实模型行为仍是软约束。验证记录位于 `outputs/prompt-v0174`。

## V0.17.3 选择题教学偏好

共享提示词 `server/question-guidance.mjs` 接入任务学习提示词与正式考察的 `learning.workflow`；出题、反馈工具说明同时提示简洁选项和作答后追问理由。默认选择这一轮只需点击，解释通常在下一轮开放问题中完成；答错时先了解实际推理，再针对误区讲解。已说明充分、不会作答或明确要求讲解时可调整节奏，比较推理过程的题目也可适当保留理由。

这些仅为柔性提示词偏好：不检查选项是否带解释，不强制多一题，不增设状态或评分规则。正式考察原有反馈记录和展示时机保持不变；如需先保存反馈再追问，可暂记实际选择及理由待核实，避免提前泄露追问要检验的解释。既有题目和用户保存的提示词不改写；新处理轮次读取更新后的公共上下文。验证记录在 `outputs/prompt-v0173`。

## V0.17.2 对话内选择题

`teacher_reply`（目标规划、任务学习）和 `teacher_assessment_question` 可附 `choice:{type:'SINGLE'|'MULTIPLE',options:[{id,text}]}`，严格校验 2–8 个唯一选项，不接受正确答案或评分字段。单选点击即提交，多选选择后提交。服务端根据原题选项生成用户回答，绑定原问题消息；正式考察沿用既有轮次、反馈和证据流程，普通练习不写能力证据。

三个附加表保存题目、已选答案与请求指纹；原消息内容及历史表不改写。重复请求或响应丢失重试不重复创建作答；旧题、已答题、暂停和只读记录禁用选项。已完成目标允许的正式复习仍可点击作答。选择控件独立更新，不重建输入框及祖先、不清除草稿或附件；历史作答和考察结果可回看。

原有纯文本题目不会靠 A/B 文本猜测转换。模型新出选择题时应通过结构化字段提交；任务学习 API 明确不支持工具调用时，仅回退一次普通文字教学，不假装提供点击选项。新增原生验收 `node scripts/smoke-desktop.mjs --choices`，记录位于 `outputs/choices-v0172`，使用隔离数据与本机固定模型/手动宿主夹具。

## V0.17.1 附件与学习返回路径

普通目标讨论、规划、任务学习的附件队列按会话隔离；拖入或选择只加入待发送列表，提交时复用资料库保存并在 message_attachments 记录消息和正文版本的关联，不自动关联正式目标。上传与消息发送分别幂等，响应丢失后重试复用原结果。正式考察继续只接收原有文字回答。

每条消息最多 5 个附件、合计 20 MB。UTF-8 Markdown/TXT 可提取正文（不超过 150,000 个 UTF-16 单元）；上下文每文件最多 12,000、总计 24,000 单元，截断与未提取格式会明确标注。原文件始终可下载。附件保存在资料库不代表已成为目标主材料，也不产生学习证据。

近期队列保留原资格和顺序，突出既有学习答疑入口；数量和主题调整折叠显示。阅读器记录进入来源，返回同一任务对话、详情、学习记录或资料库。保留进入阅读器前的学习记录自动保存，返回操作本身不重复保存。只有活动弹窗可提交其进度，避免隐藏旧字段影响新任务。

验证记录位于 `outputs/ui-v0171`；新增原生 `--attachments` 和 `--workflow-return` 验收使用隔离数据库、真实文件与本机模型/宿主夹具。实际桌面体验检查与自动化验收分别记录，不能据此声称真实模型教学质量已验证。

## 接手时先核对

1. 查看 `git status --short`、分支和远端；保留用户未提交改动。
2. 查看 `package.json` 及实际目标成品的 `resources/app/package.json`。
3. 在 Windows 检查桌面快捷方式的目标、工作目录与 `--data-dir` 参数，再核对运行进程的真实 EXE 路径。
4. 读取 `http://127.0.0.1:4317/api/health`，比较 `version`、`features` 和数据目录身份。不要把源码测试当成正在运行的桌面已更新。
5. 只有修改或调试模型配置时才查询当前 DSH 注册表；不要输出凭据文件、完整提供商配置或原始服务商错误。

开发数据默认在仓库 `data/`，正式桌面数据默认在 `%APPDATA%\AI Teacher\data`，用户可另选目录。设置保存在 `%APPDATA%\AI Teacher\desktop.json`。查清实际目录后再操作，详见 [数据与升级](../README.md#数据与升级)。

| `scripts/dsh-reply-stream.mjs`、`server/reply-streams.mjs` | 受限回复正文投射与临时分片预览 |

核心分工：LLM 提议、解释和选择参数；服务端校验、执行确定性操作并持久化。用户确认仍控制正式目标、能力要求、路线、长期画像、新连接提案和目标结束等动作（已有功能分工可由主 Agent 直接设置）。主 Agent 负责工作台说明与配置，不是所有学习功能的自动后备处理者。

## DSH 接入中必须保留的约束

- 目录发现和执行共享插件来源。不要只把模型名称加到前端，或把 Qoder 写成唯一特例。
- 当前发现读取已安装 profile bundles 与覆盖配置，查询真实 `llm.listProviders()` / `llm.listModels()`。标准模型插件可自动接入；缺少依赖、动态配置或 Desktop 专用服务时应明确诊断，不承诺任意第三方插件都能直接运行。
- 目录进程使用独立运行目录；执行进程使用会话自己的 DSH home。不得为方便复用而启动全部 Desktop 插件或混用会话身份。
- 模型插件缺失的 peer 依赖在插件模块范围内解析到正在运行的 DSH。Qoder 缓存只投射明确的公开字段，不复制整个 DSH home。
- 对话选择对后续消息生效；排队的显式模型被冻结，执行中切换不改当前请求；主动重试使用当前选择。
- 同一对话复用一个 DSH 会话；不同对话共享 `ai-teacher-workspace`，会话日志和检查点隔离。恢复失败不能静默创建新会话或重放旧工具调用。
- 生成中的正文只是内存预览；`teacher_reply` 的正式 SQLite 写回是最终依据。
- 首次目录查询可能受本机插件启动、登录读取和目录网络请求影响；缓存查询与首次冷启动应分开测量。

详见 [插件模型](DSH-MODELS-V0141.md)、[模型选择](DSH-MODELS-V013.md)、[会话恢复](DSH-SESSIONS-V09.md)、[正文流式](STREAMING-V011.md)。

## 配置丢失事件与恢复边界

本次排查发现，Agent Room 自动登记使用 BEGIN/END 标记整体替换桥接配置，而 DSH 的 `llm-pi-ai` 模型段处于这段标记内部，导致其一并丢失。用户没有主动修改模型设置。

根据自动备份恢复了模型段，并追加到管理标记之外；恢复前另存了当前配置，保留其他现有内容。重新核对普通提供商和 Qoder 均可见。此次仅修复本机配置布局，没有在本仓库中修改 Agent Room 项目的实现。不要把这一恢复记录当成未来所有外部配置写入都已得到根治。

后续若目录突变，先比较源配置、备份、管理标记和当前运行时。不能仅凭文件时间变化认定用户或其他任务改过配置，更不能将旧备份整体覆盖当前文件。详情见 [恢复记录](DSH-MODELS-V0141.md#本机配置恢复记录)。
