# V0.14.1 · DSH 插件模型发现与执行

V0.13–V0.14 只读取 `llm-pi-ai` 的显式模型声明。Qoder 等插件向 DSH 运行时注册模型，因此此前既没有进入列表，也没有进入 AI Teacher 的隔离 headless 对话。V0.14.1 同时修复这两条路径。

## 行为

- 从已安装的 Desktop/headless profile bundles 及覆盖配置发现模型扩展。标准 `llm-*` 入口和直接注册适配器的模型插件均可发现，没有 Qoder 提供商名称白名单。
- 在独立的目录查询环境中启动 DSH，读取 `llm.listProviders()` / `llm.listModels()`；模型 ID、服务商名称、模型过滤和区域开关由实际适配器决定。兼容标准插件自动接入；需要额外 Desktop 服务、动态配置或依赖缺失的扩展显示诊断，不冒充可调用模型。
- 只加载模型插件，不加载整个 Desktop 界面、浏览器、记忆或其他工具 bundle。插件 peer 依赖使用正在运行的 DSH 内置版本，在插件模块范围内解析缺失依赖。
- Qoder 冷启动只复用经过字段筛选的公开目录缓存，保留模型 ID、显示名称和能力元数据，不复制登录凭据；其他插件继续由运行时发现。
- 同一注册表记录模型与执行插件的对应关系。实际对话按所选模型加载对应插件，并等待适配器就绪后才开始回合；不存在、被禁用或已移除的模型会明确失败，不静默回退。
- 列表刷新合并并发请求，缓存 60 秒；配置、插件入口变化使缓存失效。刷新按钮强制重新查询；查询中途配置变化会拒绝混用旧结果。
- 原对话选择、排队冻结和 DSH 会话恢复规则继续生效。没有 SQLite schema 变更。
- 目录查询不发送提示词；插件可能同步其模型目录并复用既有登录。只返回名称、ID、来源和固定错误类别，不向页面返回凭据、请求头、内部地址或插件原始错误。

## 验证

- `npm test`：139 项通过，包括非 Qoder 提供商、模型过滤、插件停用、配置变化、失败诊断、缓存合并及身份信息投影。
- `node scripts/smoke-dsh-local.mjs --plugin`：真实 DSH + 独立测试提供商 + 本地模拟模型，验证 MCP 回复正文流式、同会话切换模型、重启续接、取消重试、检查点恢复和工具边界。
- `node scripts/smoke-dsh-registry.mjs`：实际安装的 Qoder 插件，核对运行时目录和独立对话适配器就绪；检查前后 DSH 源配置 SHA-256 不变；没有付费推理请求。
- `node scripts/smoke-desktop.mjs --registry`：隔离学习库中的真实桌面选择器，验证 Qoder 选项、保存和刷新保留。`--model-picker` 继续覆盖五个对话入口。
- 不将目录/适配器就绪等同于全部云模型的推理成功、额度或可用性保证。非常规混合插件若依赖 Desktop 专用服务，仍需要适配，界面会报告原因。
