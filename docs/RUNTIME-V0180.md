# V0.18.0 常驻宿主、搜索与考察讲解

DSH 首次处理一段对话时启动宿主，后续消息复用该进程，直到应用关闭。各对话仍保留独立会话和工具权限，不互相继承当前任务。Codex、Claude Code 的既有启动方式保持不变。

## 常驻连接的边界

- 使用本机 DSH 的 ACP 协议。每轮恢复或创建会话、执行、关闭会话；关闭会话会保存记录并释放本轮 Agent 和 MCP 连接，宿主进程继续等待下一条消息。
- 每轮分配新的任务凭据，读取最新上下文。上一轮凭据立即失效，不复用过期工具参数。
- 模型、凭据或代理配置变化时，在下一轮更新连接。取消、崩溃和超时不会自动重复可能已完成的操作。
- 站内回复保存和 DSH 会话完整落盘分别检查；只有两者成功才更新检查点。已有会话 ID 与历史日志继续保留。
- 「模型与分工」显示当前宿主连接状态。未使用的对话无需预先启动进程，关闭应用后不在系统后台继续运行。

## 联网搜索

搜索和阅读器联网是不同能力。Qoder 模型登录或浏览器代理可用，并不代表 DSH 原生搜索服务已有凭据。

未指定搜索提供商时，自动入口优先选择已有可用凭据的原生搜索服务；没有可用凭据时，使用 Bing 公开 RSS 搜索。用户明确选择或禁用的服务设置保持不变。已有凭据发生认证或网络错误时，不掩盖该错误。

公开搜索通过 DSH 本机代理设置连接，保留 TLS 校验、超时、取消和响应大小限制。只返回真实搜索来源，不自动访问结果中的网页。访问限制、验证码、空结果或格式变化会明确报告失败。公开入口属于尽力可用服务，不承诺永久可用或覆盖所有查询。

## 考察反馈与讲解

`teacher_assessment_feedback` 保存本题评价；正式考察仍在原有允许时机展示评价。回执明确标注未发布讲解。相同回答的相同反馈可安全重试，不覆盖已保存评价，过期题号会提示重新读取上下文。

新增 `teacher_assessment_explanation`，为当前已回答题目发布独立、真实可见的讲解消息。该工具不结束当前任务；模型发布讲解后，仍可继续出下一题或结束考察。重复调用不会产生重复讲解。模型只有确认公开消息发布成功后，才能引用为“已经讲过”。

讲解与私有评分、内部推理分开；讲解本身不形成用户掌握证据。已有隐藏反馈不批量回填、不重写历史消息。此前的中性题干、简洁选项和作答后追问理由仍通过提示词指导，不增加固定教学轮次。

## 验证

验证产物位于本机 `outputs/runtime-v0180/`；不包含在分发包内。

- 真实本机 DSH：无模型调用的创建、关闭、恢复会话使用同一进程。两种本地模型适配模式均通过连续执行、实际模型切换、历史恢复、取消、检查点与重建验证，空闲不继续调用模型。
- 实际 Qoder/DeepSeek-Flash：两轮对话使用同一个宿主进程与会话；第一轮真实联网搜索成功，第二轮读取原会话继续回复，应用关闭后进程退出。
- 实际模型考察：按用户请求先调用公开讲解、再保存评价、再出下一题；所有调用成功，公开讲解排在下一题之前，私有评价隐藏，未生成掌握证据。
- 原生桌面：可见讲解先于下一题，刷新后仍显示；私有评价仍隐藏。选择题、中文输入、草稿与附件回归通过。
- 真实搜索：经已配置本机代理查询公开 Python 文档，返回实际来源。
- 将真实数据库只读备份到隔离目录后升级：100 个已有表内容保持不变，仅新增空讲解关联表，数据库完整性检查通过。
